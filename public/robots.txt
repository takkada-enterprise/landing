# robots.txt — source of truth for takkada.com crawler policy.
#
# History, because this cost two rounds to find: Cloudflare's managed
# robots.txt feature injected its own block AHEAD of this file at the edge,
# disallowing ClaudeBot, GPTBot, Google-Extended, Applebot-Extended and four
# scrapers. Editing this file could not remove it. The control is
#   Cloudflare dashboard → AI Crawl Control → Signals → "Managed robots.txt"
# and it was switched OFF on 2026-08-08, after which the live file is exactly
# this one (1,242 bytes, verified). It is NOT under Security → Bots, and the
# per-crawler Block toggles there were never the cause — they were already off.
#
# If AI crawlers go missing from the logs again, re-check that toggle first.
# Note that scripts/checkCrawlerAccess.mjs cannot detect this class of block:
# it measures edge blocking by IP and reported all-clear the whole time
# ClaudeBot was being disallowed here.
#
# Each user-agent appears exactly once with one intentional policy.
#
# /cdn-cgi/ is Cloudflare's own path (email obfuscation, challenge scripts),
# never a page. Crawling /cdn-cgi/l/email-protection showed up as a 404 in
# Search Console (2026-10-23). The Disallow sits in EVERY group because a
# crawler with a group of its own ignores the `*` group entirely.

Content-Signal: search=yes, ai-input=yes, ai-train=no

Disallow: /cdn-cgi/
